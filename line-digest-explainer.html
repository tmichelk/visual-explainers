最大の壁

Google Cloudで何度もうまくいかなかった

約2日間・10回以上の試行錯誤

当初の計画は「Googleの無料枠でGemini AIを使う」というものでした。 しかし、GoogleのAIサービスには複数の入口があり、それぞれ課金体系が異なるという 複雑さがこの問題の根本にありました。

Google AI Studio

APIキーで簡単に使える手軽なサービス

  • ✓ 設定が簡単
  • ✓ すぐ試せる
  • ✗ 無料枠を超えると「プリペイド残高」が必要
  • ✗ Google Cloud残高とは別管理

Vertex AI（Google Cloud）

本格的な企業向けのAIプラットフォーム

  • ✓ 約¥47,000の無料トライアルあり
  • ✗ モデル名の指定が複雑
  • ✗ サービスアカウント認証が難しい
  • ✗ プロジェクト設定が煩雑

実際に起きたエラーの連鎖

❌

Gemini API 429: プリペイド残高不足

AI Studioの無料枠が尽きていた。Google Cloudの残高とは別管理だと気づいていなかった。

❌

Vertex AI 404: モデルが見つからない

Vertex AIに切り替えたが、gemini-2.0-flash、 gemini-1.5-flash-001、 gemini-3.1-flash-lite-preview など様々なモデル名を試しても「見つからない」エラーが続いた。

❌

サービスアカウント認証エラー

Vertex AI用にGoogle Cloudサービスアカウントを作成し、JSONキーを発行。 google-auth-libraryで認証を試みたが、 GitHub Actions上でハングアップし処理が永久に止まった。

❌

新しいGCPプロジェクトを作っても404

AI Studioが自動生成したプロジェクトではVertex AIモデルにアクセスできないと判断し、 新規GCPプロジェクト（ai-digest-494615）を手動作成。 Vertex AI APIを有効化、サービスアカウント設定を再実施したが、それでも404が続いた。

✅ 最終的な解決策

Vertex AIを諦め、Google AI Studio（シンプルなAPIキー方式）に戻すという判断をしました。 その上で、AI Studio用に¥2,000のプリペイドをチャージ。 また、呼び出すモデルを廃止されたgemini-2.0-flashから 最新のgemini-2.5-flashに更新しました。

Vertex AI → AI Studio に変更 ¥2,000 プリペイドチャージ gemini-2.5-flash に更新

💡 この経験からの教訓

「Google Cloud」と「Google AI Studio」は同じGoogleでも別の課金システムを持つ別サービスです。 Vertex AIは本格的な企業向けで、個人の小規模ツールには設定コストが高すぎました。 目的に合ったサービスを最初に見極めることが重要です。

🔧 その他に起きた問題と解決

⏳

GitHub Actionsがフリーズし続けた（1時間以上）

RSSフィードの取得後、処理が永遠に止まったままになる現象。ログを見ても何も出力されない。

解決策

原因は fetch-feeds.js の末尾に process.exit(0) がなかったこと。 RSSパーサーがHTTPコネクションを開いたままにするため、子プロセスが終了しなかった。 1行追加することで解決。

💳

GitHub Actionsの無料枠が切れていた

ワークフローが「支払い情報を更新してください」というエラーで起動しなくなった。 プライベートリポジトリは月2000分の制限あり。

解決策

リポジトリをパブリック（公開）に変更。パブリックリポジトリはGitHub Actionsが完全無料・無制限。 シークレット（APIキー等）はリポジトリ設定に安全に保管されるため、公開しても問題なし。

📰

RSSフィードのURL変更・取得エラー

AnthropicとRedditのRSSフィードが毎回404/403エラーを返していた。

解決策

エラーの出るソースを削除し、安定して配信されているAI News、NVIDIA Blog、Microsoft AI Blogなどに差し替え。 現在は17メディアで安定稼働中。

💬

LINEに届いた記事が1件だけ・メッセージが途中で切れた

初回成功後、AIが最も重要な1件しか選ばず、また別の回ではLINEの5000字制限を超えてメッセージが切れた。

解決策

Geminiへのプロンプトを「必ず3件以上選ぶ」「要約は1文・最大50字」「全体1500字以内」と明確に指定。 メッセージ送信スクリプトには5000字超の自動分割機能を実装済みだったが、 そもそものAI出力を短くする方向で根本解決した。
