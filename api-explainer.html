WHAT IS API

そもそもAPIって何？

API（エーピーアイ）は Application Programming Interface の略称です。長い名前ですが、本質はシンプルです。
まずはレストランを想像してください。

レストランで考えるAPIの役割

👤
あなた（アプリ）
お客さん
「パスタください」
→
注文（リクエスト）
🧑‍🍳
API（ウェイター）
仲介役
注文を伝え、料理を届ける
→
依頼
🍳
サーバー（厨房）
実際の処理
パスタを作って渡す
✅ 料理（レスポンス）があなたのテーブルに届く
💡

ここがポイント

APIは「仲介役」です。相手の内部構造を知らなくても、決まったルール（インターフェース）で話しかければ結果が返ってきます。 この「決まったルール」のことをインターフェース（Interface）と呼び、それがAPI（Application Programming Interface）という名前の由来です。

REQUEST & RESPONSE

APIの仕組み — リクエストとレスポンス

APIのやり取りは、「聞く（リクエスト）」と「答える（レスポンス）」の2つだけです。このシンプルな往復が、あらゆるAPIの基本です。

1
📤
リクエスト送信
アプリが「こういう情報ください」とAPIに送る
2
🚪
APIが受け取る
内容を確認・認証する（門番の役割）
3
⚙️
サーバーが処理
データ検索・計算など実際の処理を実行
4
📥
レスポンス返却
処理結果がアプリに返ってくる
ターミナル — APIにリクエストを送ってみる 
$ curl "https://api.weather.example.com/current?city=tokyo"

# 返ってくるレスポンス（JSON形式）
{
  "city":        "東京",
  "temperature": "22°C",
  "condition":   "晴れ",
  "humidity":    "65%"
}
APIレスポンス（データ）
"temperature": "22°C"
"condition": "晴れ"
"humidity": "65%"
→
weather-app.example.com
22°C

HTTP METHODS

「何をするか」を伝えるHTTPメソッド

APIへのリクエストには目的があります。「取る」「作る」「更新する」「消す」── これを伝える動詞がHTTPメソッドです。

GET データを取得する

情報を「見る」だけ。天気確認、商品一覧の表示など。データは変更しない。

GET /weather?city=tokyo
POST 新しく作成する

情報を「送って新規登録する」。ユーザー登録、注文送信、投稿など新しいデータを作るとき。

POST /users {"name": "田中"}
PUT まるごと更新する

既存の情報を「上書き更新する」。プロフィール情報の更新など、既存データを丸ごと置き換えるとき。

PUT /users/1 {"name": "鈴木"}
DELETE 削除する

情報を「消す」。アカウント削除、投稿の取り消しなど、既存データを削除するとき。

DELETE /posts/42

📡 レスポンスのステータスコード

APIは結果とともに3桁の数字を返します。これで「成功か失敗か」がわかります。

200 成功 「はい、料理をお持ちしました」
201 作成成功 「ご注文を承りました（新規）」
400 リクエスト不正 「メニューにないものは作れません」
401 認証が必要 「会員証を見せてください」
404 見つからない 「そのメニューは今日はありません」
500 サーバーエラー 「厨房でトラブルが起きています」

REAL WORLD EXAMPLES

身近なAPIの例 — 実はあなたも毎日使っている

スマホで何気なくやっている日常の操作の裏側では、たくさんのAPIが動いています。

☁️
天気予報アプリ
東京 22°C 晴れ

裏側でAPIがやっていること

気象サーバーに「東京の最新天気データをください」とリクエストを送り、気温・天候・湿度・風速などをJSON形式で受け取っている

または
メールアドレスで登録

裏側でAPIがやっていること

GoogleのOAuth API（認可の仕組み）に「このユーザーの身元を確認してください」と問い合わせ、認証済みの証（トークン）を受け取っている

裏側でAPIがやっていること

決済APIがクレジットカード会社のサーバーと暗号化通信を行い、与信確認 → 決済処理 → 結果通知を実行している

東京の観光スポットを教えて
東京の主な観光地は浅草、新宿、渋谷など▊

裏側でAPIがやっていること

AI APIにテキストを送り、生成されたテキストをストリーミング（少しずつ）で受け取っている。ChatGPTやClaudeは全てAPIで提供されている

✨

気づきましたか？

上の4つの例に共通しているのは、あなたがAPIの存在を意識していないということです。優れたAPIは、ユーザーにその存在を感じさせません。まるで空気のように、裏側で静かに仕事をしているのです。

WITH vs WITHOUT

APIがある世界とない世界

❌ APIがない世界

  • ✗ 天気情報が欲しければ、自分で気象観測の仕組みを構築する
  • ✗ 決済機能が欲しければ、クレジットカード処理を自前で開発する
  • ✗ 地図を表示したければ、地図データを自分で作成・更新する
  • ✗ ユーザー認証はパスワード管理からセキュリティ対策まで全部自前

膨大な開発コストと時間。バグのリスクも高い。

✅ APIがある世界

  • ✓ 天気情報は天気予報APIに問い合わせるだけで取得できる
  • ✓ 決済はStripe APIに任せれば数行のコードで完成
  • ✓ 地図は地図APIで高品質な地図を即表示できる
  • ✓ ログインはGoogleやAppleのAPIで安全に認証できる

「自分が本当に作るべきもの」に集中できる。

SUMMARY

まとめ — 覚えておきたい3つのこと

01

APIは「ソフトウェアの注文窓口」

レストランのウェイターのように、あなた（アプリ）とサーバーの間を取り持つ仲介役。相手の内部構造を知らなくても、決まったルール（インターフェース）で話しかければ結果が返ってきます。

02

あなたはすでにAPIユーザー

天気予報、SNSログイン、地図検索、オンライン決済、AIチャット。気づかないうちに、あなたの日常はAPIに支えられています。APIは特別な人だけのものではなく、全員の生活を支える基盤技術です。

03

APIで「車輪の再発明」がなくなる

すでにある優れた機能をAPIで借りることで、自分は「自分にしか作れない部分」に集中できます。開発スピードが上がり、品質も上がり、保守の手間も減る。これがAPIの最大の恩恵です。

💡

APIは「知っている」だけで世界が広がる概念です。

次にアプリを使うとき、「この裏側でどんなAPIが動いているんだろう？」と想像してみてください。
天気予報の数字も、ログインボタンも、AIの返答も、すべてAPIが繋いでいます。
テクノロジーの見え方が、少しだけ変わるはずです。
